# Рефакторинг «лайки → оценки» (branch: add-marks)

## Контекст

Задача «Лайки → оценки»: вместо бинарных лайков у фильмов вводятся оценки 1–10
(1–5 — отрицательные, 6–10 — положительные). Рейтинг фильма — среднее арифметическое
всех оценок (дробное значение). Рекомендации строятся на похожести оценок пользователей.

## Варианты реализации

### Вариант A (выбран, текущее состояние)

Поле `Film.likes` (Set<Long>, список оценивших) **полностью удалено**.
Вместо него в модели только `Film.rating` (Double, @Transient = вычисляемое поле,
не хранится в таблице `films`).

- Оценка фильма: `PUT /films/{id}/marks/{userId}?value=N` (N от 1 до 10)
- Снятие оценки: `DELETE /films/{id}/marks/{userId}`
- Отметку поставившего пользователя определить из ответа **нельзя** —
  API отдаёт только агрегированный `rating`.

### Вариант B (запасной, если упадут Postman-тесты)

В модели остаётся `Film.likes` как список пользователей, поставивших оценку,
и дополнительно добавляется `Film.rating` (Double). То есть и список, и агрегат.

- Оценка фильма: `PUT /films/{id}/marks/{userId}?value=N`
- Снятие оценки: `DELETE /films/{id}/marks/{userId}`
- Отметку поставившего пользователя можно получить из `Film.likes`.

## Как вернуться с варианта A на вариант B

> Применять только если Postman-тесты упадут на проверке ответа, ожидающего список
> `likes`/`likedBy` у фильма, и ревьюер подтвердит, что список оценивших обязателен.

1. В `model/Film.java` добавить обратно поле списка пользователей, поставивших оценку:
   ```java
   // @Transient — вычисляется из таблицы marks
   private Set<Long> userIds;
   ```
   (JSON-имя согласовать с тестами — например `likes` через `@JsonProperty("likes")`,
   либо именовать поле сразу `likes`.)

2. В `FilmDbStorage.enrichFilms()` рядом с расчётом `rating` собрать список
   пользователей для каждого фильма (уже грузится таблица `marks`):
   ```java
   Map<Long, Set<Long>> userIdsByFilm = new HashMap<>();
   // в том же запросе: SELECT film_id, user_id, "value" FROM marks WHERE ...
   // и заполнить оба словаря
   ```
   `film.setRating(avg)` и `film.setLikes(userIdsByFilm.getOrDefault(film.getId(), Set.of()))`.

3. То же самое в `UserDbStorage.enrichFilms()` (там, где сейчас считается `rating`).

4. `InMemoryFilmStorage` — при желании вернуть поле с оценившими пользователями
   (хранить `Map<Long, Set<Long>> userIdsByFilm` или расширить `marksByFilm`).

5. Все изменения — только доработка существующего кода на оценках. Таблицу `likes`
   в БД **не восстанавливать** — она уже заменена на `marks` (шаги 1–2), и схема
   пересоздаётся при старте приложения. Откат схемы не требуется.

## Текущий прогресс (шаги)

- Шаг 1 — схема: таблица `marks` вместо `likes`, `Film.rating`. Коммит `b9422a0`.
- Шаг 2 — базовые операции: `addMark`/`removeMark`, расчёт `rating` в enrich,
  API `/marks` вместо `/like`, карантин (переписывание) старых тестов. Коммит `2c3e295`.
- Шаги 3–8 — следом: рейтинг/популярность, режиссёр, рекомендации, тесты, feed-события.
